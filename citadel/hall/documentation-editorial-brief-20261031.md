# Documentation Editorial Brief (KING program) — pilot

**Standard:** book, not raw machine prose. README = entry volume; USER_MANUAL = operational handbook; LINEAGE =
historical chronicle. Every volume needs an editorial architecture, consistent terminology, narrative continuity,
diagrams, version accuracy, technical review and independent proofreading.

## Editorial architecture
### README (entry volume)
1. What AGI is (one paragraph + one diagram).
2. What is stable now (version, baseline, what is not claimed).
3. Quick start (install/verify in minimal steps).
4. How the organism is organized (identity, memory, awareness, governance, verification).
5. Citadel and the living ecosystem (Council, Hall, Divisions; how direction/review works).
6. Evidence and limits (independent verification, no overclaiming).
7. Where to go next (manual, lineage, release notes).

### USER_MANUAL (operational handbook)
- Roles and authority (Owner, KING, DSH, Kilo, community).
- Install/upgrade/rollback without destructive steps.
- Memory taxonomy/visibility and safe use.
- Awareness/host model and continuity limits.
- Governance/decision ledger and how to request changes.
- Verification/evidence requirements.
- Troubleshooting and support boundaries.

### LINEAGE (historical chronicle)
- Volume/part/chapter structure, not a changelog.
- Each generation: context, design decisions, evidence, limits, what changed, what was preserved.
- Machine appendix separated from narrative; artifacts addressed by hashes/tags.
- Every chapter cites evidence and a rollback baseline.

## Editorial workflow
1. Outline and terminology glossary approved by KING.
2. Draft from verified evidence, not invented claims.
3. Technical review (DSH/King), then independent proofreading (Kilo/Claude via DSH if authorized).
4. Version matrix and release-pin check.
5. Publish only after editorial acceptance; keep machine facts in signed manifests.

## Pilot: README rewrite first
- Deliverable: one entry volume with the seven sections above, one architecture diagram, version/limits box.
- Then USER_MANUAL; then LINEAGE.
- Do not rewrite all volumes in one pass; preserve git history and rollback.

## Acceptance criteria
- A newcomer can state what AGI is, what is stable, and what is not claimed after reading README.
- No version drift or unverified claims.
- Terminology consistent across the three volumes.
- Independent proofreading recorded.
